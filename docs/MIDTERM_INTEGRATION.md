# Native study lists and reusable exercise modes

Hanzi Mastery remains the existing RemNote plugin. Ordinary native Rems are the content authority. The runtime reads their current fronts, backs and exercise-setting children; synced plugin storage holds the selected list ID, practice results and sessions. It does not mirror the exercise bank. `classicalChinese.ts` is an optional seed-import adapter, and can be retired without removing the exercise components or the native cards.

## Use the prepared list

Use the current Hanzi Mastery package, then run **Hanzi Mastery: Midterm / course study**. Under **Connect a RemNote study list**, paste the parent list's Rem ID or document link and choose **Connect list**. Keep all seven sections under that parent. **Reload Rems** picks up native edits and invalidates a stale session when its question content changes; display-only word-order and particle hints preserve the session. Practice a section, mode, missed items or the entire list. Normal RemNote flashcards remain usable independently of the plugin. See [the README](../README.md#version-and-installation) for source and hosted-distribution status.

Native JavaScript execution is not requested in 0.4.13: the required manifest field is `requestNative: false`. Sandboxed study retains course exercises, ordinary queue integration, native scheduling, saved progress and paused-card state. Native execution is separate from RemNote's native cards and scheduler, and it is not inherently required for microphones. The existing recorder captured and played a clip inside a sandboxed, cross-origin Chromium fixture when the host supplied both `allow-same-origin` and microphone delegation. The inspected signed-in RemNote 0.4.4 frame had neither; reproducing it rejected capture before recording. The pinned SDK 0.0.46 has no documented recorder bridge or iframe-permission option. A separate recording-window test prototype returned a clip to the opaque sandbox in Chromium, but is not shipped or verified in the iPhone app. See the README for the permission matrix and alternatives. Physical iPhone capture remains unverified. Use an M4A from Voice Memos via **Use an audio file**, or read aloud and self-assess without recording. See [RemNote's permission documentation](https://plugins.remnote.com/advanced/permissions).

The private ZIP importer creates native cards if no list is connected. When the same list is already connected, it keeps the existing edited cards and imported SRS. Each reading exercise plays its corresponding line clip. Audio entries point to those Rem IDs; the loader reads their current native media URLs. Other devices can load those attachments through RemNote without another ZIP upload. A network connection is needed for initial playback. The SDK has no binary-upload API, so the media migrations used RemNote's native Anki importer; their temporary audio flashcards were converted to ordinary media Rems. The ZIP's device-local audio store remains an optional fallback for the supplied originals; the separately uploaded line clips use their native attachment references. PDF files are ignored before decompression. Keep the window open during a native-card import; its counter reports progress. ## Authoring contract

A normal forward card supplies its prompt and accepted answer. Separate alternatives with ` | `. An optional ` Explanation: ` introduces the model explanation on the same back. A child Rem starts with `Hanzi Mastery exercise: ` followed by JSON containing a stable `id`, `section`, `mode`, `kind` and `source`. Optional fields include `glyph`, `referenceGlyph`, `choices`, `audioId`, `syllables`, `showPinyin`, `selfGrade` and `input` (`pinyin` or `text`). Kinds are `text`, `choice`, `oral`, `circle` and `writing`. Prompt, accepted answers and explanation are read from the parent card rather than duplicated in that child. Writing reads its one-character target from the native answer. `referenceGlyph` displays a separate source character without revealing the writing target. Oral Pinyin starts visible unless `showPinyin:false`; native reading fronts also include the supplied syllables.

The parent list has one `Hanzi Mastery list: ` settings Rem containing schema version 1, `studyPackId`, section labels, audio metadata, `audioVersion` and notes. An audio entry can include `remId` for a native audio/media Rem. The loader resolves its current URL without saving a second URL copy in plugin storage; recording bytes stay in RemNote's file storage. Entries without a native attachment use the local ZIP fallback. The canonical local-audio manifest hash is independent of question edits, input-file order and device locale. Keep item IDs stable when editing to retain practice history. New content can use the same modes without introducing a new plugin feature.

## Conservative SRS migration

The 72 newly imported radical recall cards use the recorded **Pinyin skill** as their scheduling basis. Aggregate meaning, pronunciation and writing statistics remain archived beneath each card and are not combined into invented review events. The estimator rounds lifetime cadence down, caps initial intervals at 1–3 days, shortens them for low source levels/recent errors/error rate, and seeds ease at 180%. Account-specific interval distributions remain in the private audit. Past due dates stay overdue. The cap applies only to the migration seed, not future scheduling.

One known latest-review timestamp/outcome is transferred per card. Its Good/Again mapping, interval, prior interval and ease are estimates. Earlier individual reviews and response times are unavailable and were not invented. Source aggregate attempts/errors are repetition/lapse proxies in the bridge package; RemNote's visible history contains the transferred anchor, not all aggregate attempts. Future native ratings use RemNote's current scheduler. Completed linked course exercises now append Good/Again through the RemNote scheduler by default; the dashboard option can disable schedule updates. Paused cards stay paused. Imported history is retained, and past plugin practice is not replayed.

Reading practice hides the instructor reference until you confirm a spoken attempt or finish an optional recording. Completed playback enables oral self-assessment. Unavailable audio can be skipped with no result. Popup scrolling is bounded independently of the RemNote modal and returns to the top on the next exercise.

Queue updates verify the linked exercise identity and one forward card, append with the supported card API, then read back history. Durable per-event receipts prevent duplicate callbacks. Ambiguous failed RPCs are reconciled without resending; there is no SDK idempotency token or atomic cross-device transaction. Do not clear an unresolved receipt to force a retry. Unlinked/ambiguous cards are preserved. No pause flags or prior reviews are rewritten. RemNote excludes paused cards from its per-Rem card lookup, so first-time paused-list discovery reads native card identities through the public Card API and caches only IDs belonging to the connected list. ## Persistence, privacy and removal

Word-order cards can include aligned `syllables` and `glosses` arrays in their existing exercise-settings Rem. These provide visible character-by-character pronunciation and meaning, without revealing the relation or phrase translation. The ordinary native flashcard front includes the same hints. Editing only these aids preserves the session version and its saved place; questions, answers and identities continue to participate in version checks. Enriched handoffs can supply `pinyin_syllables` and `character_meanings` on word-order rows. Older un-enriched handoffs remain valid and do not invent hints.

Course sessions make one pass through their fixed selected IDs. Each section and All sections have their own saved list, position and draft; Resume displays the selected section's slot and names its original activity. Existing single-session saves are copied to the section inferred from their saved IDs before a new session can replace the legacy pointer. Starting another session replaces only that section's slot, never its completed exercise results. Missed activities are not inserted again. After finishing, Practice missed selects the most recently failed activities. Practice unstudied selects activities without a saved attempt, including no-result skips. Both focused buttons respect the section and activity filters. They use the existing synced course progress and do not change native card pause flags or replay old schedule updates.

Writing uses the existing thresholds (60/75/90/95% by default), reveal/forgotten failure rules, ledger and separate-day promotion logic through a course-specific storage prefix. Existing handwriting and native cards are untouched. First submitted answers freeze before reveal; serialized writes and read-back confirmation make result retries idempotent. Drafts save after 400 ms, on submission and on returning to the dashboard; interrupted writing tests restart while completed results remain saved.

Simultaneous changes from multiple devices are not atomic. There is no new durable offline outbox; cold offline startup is unverified. RemNote attachments avoid repeated manual uploads, but physical iPhone sync/offline caching and all device codecs remain unverified. The optional local-audio fallback uses IndexedDB byte buffers and can be evicted by clearing site data. Microphone recordings are optional, limited to 20 seconds, kept in memory and never uploaded by these modes. PDF/audio bytes, private attachment URLs and personal history stay out of the public repository and plugin upload ZIP.

Session saves read the current slot before writing. Older cursors within the same fixed list are rejected; a different session can replace a slot only through an explicit start action. The UI adopts the accepted snapshot. Closing an untouched popup performs no session write, while pending drafts still flush. Submitted first answers remain frozen. A legacy client’s farther cursor can advance its matching section save during loading. These guards prevent the reproduced stale-popup rewind but do not establish atomic cross-device updates.

**Disconnect list (keep Rems and progress)** retains the native notes/cards and practice keys. Reconnect the same parent list to restore it. Retiring the midterm adapter does not require deleting native cards or resetting progress. Reusable mode components can remain in future versions.
