# Installation and distribution status

For hosted installation, open the [unlisted plugin page](https://www.remnote.com/plugins/hanzi_mastery_handwriting_v1) while signed into the account used by your devices. Install/enable the approved version. In a compatible writing review, expect a Hanzi Mastery section with **Begin test**, followed by the writing square. Existing correctly tagged cards do not need to be recreated after a plugin update.

For local development only, run `npm ci`, `npm run build`, then `npm run dev`. In RemNote's Plugins developer tools, load the unpacked plugin from `http://localhost:8080` using **Develop from localhost**. The server binds only to this computer. Keep it running while testing; `npm run dev` does not hot-reload source changes, so rebuild after edits.

The ZIP in `release/` is a compiled RemNote upload package, with the manifest and widget bundles at its root. The official SDK validator checks it before packaging. It does not establish RemNote approval or successful installation.

The official [GitHub release](https://github.com/j5cfk7qm49-web/hanzi-mastery/releases/tag/v0.4.0) contains the compiled ZIP, matching source and checksums from commit `5d2bd9022b93b2ec8374bd52a64c9c3538a4c54f`. RemNote showed a successful upload for the original `hanzi_mastery_handwriting_v1` ID; Check for Updates then changed the signed-in desktop installation from 0.3.5 to 0.4.0 and loaded its versioned hosted index bundle. The exact uploaded ZIP SHA256 is `9bd9c72c8ed31ae4055fc1569d289b019a4e86458e3f4decc88977dfe56727c4`.

This update adds all eight study modes, Hanzi Writer for meaning → characters, four-choice recognition, dictionary import/editing, native vocabulary lists and shared review UI. The pinyin toolbar uses standalone diacritics without a neutral-mark button, and tone recall uses four quadrants with neutral in the center. Physical iPhone/Pencil acceptance remains outstanding.

GitHub publication and RemNote distribution are separate steps for this plugin. After publishing the GitHub 0.4.0 release, RemNote’s completed Check for Updates still showed 0.3.5. Uploading the compiled ZIP through Build → Upload plugin made 0.4.0 available. The manifest’s repository URL is for source review; this repository’s GitHub Actions workflow tests/builds but does not deploy to RemNote.

The desktop development entry still displayed 0.2.0 and the localhost URL on October 20, but the user subsequently confirmed 0.3.1 on the phone. The desktop entry therefore does not establish the phone's installed source or version. A localhost URL refers to the device opening it, so the desktop's loopback-only development server does not provide a phone installation. "Enabled on Mobile" is not an installation or runtime test.

On the phone, open Plugins → Manage and use **Check for Updates** if that control is available. Reopen RemNote and check that Hanzi Mastery displays 0.4.0, then open an existing writing review. The update control and hosted 0.4.0 loading were verified on desktop; the phone's exact update-menu layout has not been verified. GitHub ZIPs are not an iOS sideload mechanism. A waiting message distinguishes an activated review that cannot bind; HM-START indicates a caught render/effect failure. Neither is a successful handwriting result. A completely blank view may instead mean that RemNote did not mount/activate the view or that failure preceded the error boundary.

For future uploads, use the Plugins **Build** tab → **Upload plugin** with the compiled ZIP. `unlisted: true` requests personal/unlisted distribution. RemNote's published policy still requires review, including a public source URL. After approval, use the [unlisted plugin page](https://www.remnote.com/plugins/hanzi_mastery_handwriting_v1) and enable it on the devices you use. There is no documented universal “install any local ZIP directly into iOS” route.
